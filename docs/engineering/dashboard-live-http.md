# 工作台汇总读取与真实 HTTP 验证

日期：2026-11-03。负责人：Web / Backend。沿用已定版的 API-M01 和 OpenAPI 1.51.1 / 143 操作，无新增路由、权限、迁移或业务写入协议。

工作台使用生产 `readSummary` 读取器：同一取消信号下，先读取当前身份，再读取唯一业务汇总接口，最后复核身份。账号、用户 ID、角色键集合、权限键集合或商家 ID 改变时不发布该次结果；显示名称和集合排列变化不改变授权键。所有请求 no-store，不传客户端用户/商家 ID，不拼接业务列表模拟汇总。

七类面板逐字段投影，明确区分 null 与零。计数为非负安全整数，各状态之和必须等于 total；时间必须为服务端标准 ISO 形式。收益保持两位小数字符串，校验 CNY / all-time / all 或 merchant，不转换为浮点数、不自行截断汇总金额。附加属性全部丢弃；未知或不完整响应进入固定错误状态。读取器还拒绝当前身份无权展示的非 null 面板及错误的收益范围。最终数据范围和真实数值仍由服务端事务决定，不能通过前端规则替代 SQL 授权。

隐藏页面或 pagehide 时清除当前面板并取消读取；返回后可显式重新读取。刷新覆盖旧请求，卸载永久取消本实例；传输忽略取消时的迟到成功或错误也不能覆盖当前视图。身份键变化会重挂载内容，错误状态保留脱敏 traceId 与手动恢复入口，不回显服务端异常正文。

`/auth/me` 依现有协议需要 `account:profile:read`。本轮不会自动向业务角色补权，也不移除该鉴权要求。所谓“无业务面板”夹具角色持有管理入口及本人资料读取权限，七类业务面板均无对应 grant；它不是完全无权限账号。

生产汇总在同一个只读 RepeatableRead 快照中计算；前端不能订阅未出现在 CurrentUserVO 中的数据范围配置变化，也不保证已开始的数据库快照追溯反映撤权。下一次读取仍由后端重新解析完整权限和范围。生成响应与最终身份查询之间也存在正常并发窗口，不声称实现跨请求原子授权。

管理 HTTP 套件现为 31 项，新增四项：管理员七类面板；无业务权限返回 null；商家归属/保护面板/读取期间真实撤权；多角色范围冲突拒绝。调用生产读取器、实际编译 Nest 和全新 PostgreSQL/pgvector，使用 Node Cookie 适配器。两个商家的收益通过专用夹具直接准备为 123.45 与 678.90；全局为 802.35，本人商家为 123.45。自定义角色即使拥有 RAG 和全局收益 grants，也不能冒充内置 system_admin。真实授权修改发生在汇总响应与最终身份查询之间，读取器拒绝旧结果；同一登录会话按新权限读取全 null。

后端另核对两条收益的雪场、金额、来源、录入人和备注保持；客户端快照的账号/商家计数与金额吻合。既有知识版本/首次发布时间/软删除、七条知识事件和审计、RAG 版本/分块及事件审计、原事件重试预算与唯一审计、商家隔离、拒绝 trace 和会话退出断言继续通过。汇总本身只读；测试中的角色授权命令会按既有规则产生审计。

首轮 29 通过、2 失败，因为测试角色遗漏已要求的本人资料读取 grant，在 /auth/me 被拒绝。仅修正夹具授权，在新临时库完整通过；两轮均停止，失败日志保留。模型/SSR 和实际 HTTP 分开计数，不把 31 项重复运行累计为新增覆盖。
