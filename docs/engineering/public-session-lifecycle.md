# 官网会话读取与凭证操作

日期：2026-11-03。负责人：Web 官网。范围：现有登录、退出、当前用户与文章收藏身份投影；沿用 OpenAPI 1.50.2 / 143 操作，没有新增产品接口、依赖或数据库迁移。

## 当前实现

会话逻辑留在 `apps/web/src/platform/auth/`，管理端和 App 各自维护其认证实现。Provider 只负责路由/焦点、React 状态和交互；PublicSessionRun 编排读取、写入和生命周期；PublicSessionFence 记录浏览器内正在处理或结果未知的凭证操作。共享 api-contracts 包继续只提供生成类型和通用传输，不放入官网业务会话。

每次路由切换或焦点重查，当前身份立即隐藏，ready=false、revision 更新，文章收藏据此停用旧账号子树。路径变化的首帧也隐藏旧状态，不等待 effect 清理；公开页面 children 始终保留。当前用户读取使用 no-store、AbortSignal、单次并发和生命周期标记，旧读取/旧按钮不能更新或操作后续路由，包括离开后再次回到同一路径的情况。

运行时校验当前用户的编号、角色、权限、菜单和商家投影，只保留声明字段，不把额外敏感字段带入 Context。菜单递归有防御性深度保护。登录账号 trim 后小写，密码保留原文；按现有登录 DTO 校验账号 1–50 字、密码非空且不超过 72 UTF-8 字节，注册的 8 字节下限规则不用于登录旧账号。页面提交后立即清除该表单的密码输入。

登录响应必须符合浏览器协议、账号匹配且到期字段有效，不能向浏览器返回原生 access/refresh token。退出必须返回 loggedOut=true。即使响应合法，也重新查询当前 Cookie 对应身份，不直接采用登录响应中的旧 currentUser。会话检查沿用既有 HTTP 客户端的正常 Cookie/CSRF 与过期刷新流程；检查不会重放登录或退出命令，但可能触发正常 refresh。

同步门禁在请求前获取，覆盖登录和退出，阻止 Enter/按钮重复提交。请求已发出后，换路由或卸载不会假设它被撤销；其结果仍负责释放或保留浏览器内门禁。该门禁在同一浏览器 JS 环境中的 Provider 重建间共享，SSR 每个实例独立，不共享用户资料，也不存储密码、Cookie 或 Token。

网络错误、408/5xx、异常成功响应保留结果未知状态；隐藏身份，暂停登录/退出，焦点和路由变化不自动重试。用户可显式“检查当前会话”；有效身份或最终 401 仅确认当前会话状态，再解除同一代次的保护，不声称证明此前命令是否执行。核对失败、响应异常或仍在处理时继续保持保护。其他 4xx 视为明确拒绝，重新读取会话并显示通用错误，不展示服务端敏感详情。

## 验证与限制

新增三个测试文件共 53 项，覆盖响应投影、UTF-8 输入、首次路由显示、读取取消/并发、旧动作、同步写锁、当前 Cookie 再核对、错误分类、未知结果恢复、Provider 重建及旧核对不能释放新门禁。三个页面回归先复现失败再修复，日志 public-session-provider-before.log 保留。与既有文章收藏 11 项合计 64 项、官网 TypeScript 检查通过；已纳入 `pnpm test:web-article-favorites` 和完整 check/CI。首次类型检查发现测试记录可能不存在，已修正可选访问并复验。

测试使用 Node/SSR、请求与路由替身；它们不能证明真实浏览器 Cookie、自动填充、跨标签页、浏览器前进/后退、实际 API 或设备行为。内存门禁不跨浏览器刷新、标签页或设备，没有新增服务端登录/退出幂等协议；其他标签页的在途 Cookie 响应仍存在竞争，后端授权始终是最终边界。API 不可用时保留公开浏览，个人投影停用并允许显式检查。
