# 事件运维读取与重试恢复

日期：2026-11-03。负责人：Web。契约：OpenAPI 1.51.1 / 143 操作，沿用已定版的事件列表及人工重试协议。本轮没有新增接口、权限、数据库迁移或跨设备幂等协议。

事件页面现在把 HTTP 响应视为未知输入。列表和重试回执只投影十二项获准的事件元数据；检查 UUID、状态、数据库整型范围、时间、分页数量、hasNext 与重复 ID，丢弃 Payload、LastError、LockToken 和其他附加属性。没有自行增加 Attempts 必须小于 MaxAttempts 或状态与时间的关系限制。

列表读取前后均使用同一取消信号重新读取身份，并比较账号、用户 ID、角色键与权限键集合。当前身份不完整、授权变化、请求取消或响应异常时不发布该次列表。原事件定位仍采用一毫秒时间窗口与精确 EventId 匹配，兼容 PostgreSQL 微秒存储。

页面隐藏或 pagehide 时取消读取、清除列表和选中项、关闭当前写门禁；visibilitychange/pageshow 返回可见状态后恢复门禁，列表由用户手动刷新。未完成写入保留同一浏览器内的账号级恢复记录。即使迟到响应成功，离开的页面也不能解除保护或触发成功回调。写入返回成功后还要复核身份；该复核发生 401、403、429、503 或身份变化时，均保留待核对记录，不能将复核失败当作写入被拒绝。

同一账号的多个组件共享恢复记录，并在实际发送前原子占位，阻止重复发送。读取原目标并成功刷新当前列表后才能登记当前版本的核对凭据；未读、请求未结束或任何记录版本变化时，人工确认均不能解除保护。隐藏页面会清除本地核对状态，返回后需要重新读取。恢复记录仅保存不可变目标定位与提交前次数，不保存原因、Payload 或异常详情。

恢复记录在内存中，不覆盖整页刷新、独立标签页、另一设备或浏览器关闭；人工核对后的再次操作仍以服务端当前状态为准。取消请求不证明服务端撤销，读取当前 pending 也不证明 Kafka 已投递。服务端授权、事务与审计仍是最终约束。

验证记录见[本轮证据](../validation/event-lifecycle-20261103.json)。单元测试覆盖响应异常、身份变化、取消与迟到响应、组件间竞争、核对版本和写入后身份接口失败；页面渲染检查使用 SSR。另通过生产读取器与门禁进行 27 项真实 Nest/PostgreSQL HTTP 联调，并核对原事件 ID、Attempts=5、预算 5→13、唯一重试审计及既有知识/RAG 持久结果。真实 React 点击、浏览器 Cookie/CORS、可见性事件及 BFCache 往返仍需浏览器验收，不能用模型测试或 SSR 替代。

既有联调范围与运行方法见[知识及事件联调](content-events-live-http.md)和[管理端 HTTP 验证](admin-authorization-live-http.md)。整体目标仍未完成，D-49、D-50、D-09 等未定版事项保持待办。
