# 参赛级品质目标与自检

日期：2026-11-06。用户要求以 Awwwards、Webby Awards、FWA 能获奖的品质为目标。本项目据此提高设计与工程标准；这不是已经获得提名、获奖或外部评审通过的声明，也不设置一个自打分数来伪装达标。

## 依据与适用面

- [Awwwards 官方评价体系](https://www.awwwards.com/about-evaluation/)：设计 40%、可用性 30%、创意 20%、内容 10%。本轮读取了官方页面，而非从记忆补造权重。
- [Webby 官方评价入口](https://www.webbyawards.com/judging-criteria/)：本轮请求返回 403，未核实其当前细则，不借用 Awwwards 权重冒充 Webby 规则。
- [FWA 官方介绍](https://thefwa.com/about)：强调数字设计卓越；本轮可读页面未公开足够的细则，因此不编造其评分权重。

原始资料保存在 `D:/linji-local/20261106/ui-research/award-pass/`。优秀作品的视觉表达不能替代可用性、内容真实性与工程完成度。官网是品牌与探索入口；管理端是任务操作界面，不应为了“炫技”牺牲表格密度、授权流程或可读性。

## 自检与实际修正

| 维度        | 发现的问题                                   | 已采取的调整                                                                   | 验证方式                                                       |
| ----------- | -------------------------------------------- | ------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| 品牌/构图   | 冬日小屋偏泛旅游，与滑雪的山地感关联不足     | 雪山大图与蓝色文案区保持非对称构图；黄色标题，手机按阅读顺序堆叠               | 查看桌面、平板、390px/320px 的实际截图                         |
| 版式节奏    | 三个同构白色空状态大卡容易形成模板感         | 标题/探索链接与真实状态分栏，黄/橙章节保持完整留白；有数据时不改变卡片业务字段 | 真实空接口浏览器检查 + 有内容服务端渲染测试                    |
| 动效/可达性 | 静态首屏缺少进入体验，但重型动画不适合业务站 | 只有一个 1 秒雪景展开，内容默认可见；减少动效时直接静态呈现                    | 读取动画名称/次数，等待结束后截图，检查减少动效                |
| 素材/性能   | 首屏依赖运行时第三方图片请求                 | 本地响应式 WebP，桌面 227,106 字节，手机 52,262 字节，高优先级加载，固定图框   | 检查实际 currentSrc、自然尺寸、载入成功；不是生产 CWV 认证     |
| 内容真实性  | 缺封面时库存风景会被误解成雪场/用户图片      | 雪场提示缺图；文章/动态无封面则使用文字卡片，保留图片数量和全部业务信息        | 无封面/真实封面/空数据/服务失败测试                            |
| 操作效率    | 后台多色外壳和同权重数字影响扫描             | 白色外壳、蓝色选中、主/次统计层级；状态细项紧凑排列                            | 真实后台读页面、未提交表单、抽屉与手机检查                     |
| 容错/响应式 | 配置名称变长、登录展开或缩放可能暴露布局问题 | 首屏可按内容增高、动态元数据允许换行，不裁掉长名称和操作                       | DOM-only 合成长名称压力测试、200% CSS zoom、展开登录、键盘锚点 |

按“检查 → 批量修正 → 最终复验”执行，不以无限微调替代交付。测试发现移除动态占位图后图片数量不再显示，已保留无封面时的数量文本并复验；另一次新增测试的检查范围过大，已使用正确的 Next 静态图片元数据桩和真实封面用例校正。初期误用 Vitest 范围的失败日志也保留，不掩盖过程问题。

## 结论与未覆盖项

最终工程结果见[本轮验证报告](../validation/ui-design-research-20261106.json)。本地视觉、交互与工程基线已进一步提高，但**不能据此宣称达到三个奖项的获奖线**。

参赛准备仍有明确缺口：

1. 线上缺少公开雪场、文章和动态，尚不能验证真实内容驱动的完整探索体验；不擅自发布假内容。
2. 当前使用库存雪山意象，尚缺品牌专属摄影、运动影像或经过授权的原创视觉资产。
3. 尚未获得独立设计评审、目标用户测试、真实弱网/低端机及生产 Core Web Vitals 数据；CSS 缩放不是全部浏览器/系统缩放测试。
4. 本轮只优化 Next.js 网页；未重新部署、未更新 Expo/APK，也未覆盖所有角色/所有业务点击流程。

这些是可核查的未完成条件，而不是继续叠加动效就能解决的问题。用户的获奖品质目标继续作为后续设计方向，工程放行与外部获奖判断分别记录。
