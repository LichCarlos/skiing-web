# 角色读取与授权目录校验

日期：2026-11-03。负责人：Web 维护者。对应 ADM-07、ADM-08、API-M03，沿用 OpenAPI 1.51.1 / 143 操作，不增加 API、业务字段或数据库迁移。

角色列表、详情和编辑准备统一使用 `role-queries.ts`。读取前验证本地身份并读取 `/auth/me`；收到业务结果后投影与校验，再次读取身份，只有账号、商家、角色及 grants 与原上下文一致才交给页面。该检查只能拒绝已经观察到的变化；数据范围仍由后端每次请求独立判定，不能称为跨请求原子快照。

`role-response.ts` 显式保留生成 VO 中的字段，校验角色编号、状态、计数、默认范围、嵌套资源范围及分页一致性，过滤未知响应字段。允许合法后续空页和可省略的历史角色说明。授权页同时读取并投影授权快照、权限树和权威资源目录：检查重复编号/资源/字段策略、布尔读写值、selected 的编号、权限树结构与深度。历史孤立权限编号、旧未知资源键仍能展示和原样保留/移除；不通过前端常量推断商家身份，也不在本端新增授权资源白名单。

列表、详情和授权页在隐藏或 pagehide 时取消读取，清空已读数据、编辑目标和授权输入；重新可见不会自动重放请求或写入，需手动刷新。页面查询闭包核对当前参数，编辑准备使用同步门禁。隐藏页面禁止提交，未知写入核对在隐藏后失效；较早核对的迟到结果不能重新解除保护。写入仍使用原角色写门禁、待核对账本和后端事务；创建/更新及授权成功响应也必须通过相应 VO 校验。

专项测试覆盖返回值投影、分页/嵌套异常、历史引用、身份变化、取消、隐藏和延迟结果。页面生命周期用模拟 Hook 和 EventTarget 验证，不等于真实 React/浏览器/BFCache 验收。真实 HTTP 套件另以生产读取器、Cookie 客户端连接编译后的 Nest 和隔离 PostgreSQL，验证完整角色及授权目录、后续空页、自定义角色 selected 范围与范围外拒绝，以及真实授权 API 在读取期间撤销 grant 后的拒绝。

结果见[本仓证据](../validation/role-reads-20261103.json)和[后端联调边界](../../../backend/docs/engineering/role-read-http-validation.md)。Cookie jar 使用 Node 测试适配，没有启动 Next 服务或真实浏览器。三仓冻结安装、检查与构建/导出的完成状态以本轮证据为准；Kafka、真实供应商、容器、原生签名包及远程 CI 不在本次验收范围。D-49、D-50、D-09 保持待确认。
