字段定义与字段分组的请求一旦发出，切换路由、重新挂载组件或身份重新读取不能抹掉结果未知的记录。`apps/admin/src/features/custom-fields/field-recovery.ts` 在当前浏览器标签页内，以账号 ID 和实体类型为键保存写入状态。记录仅有操作令牌、是否涉及分组、是否仍在请求中，不保存表单正文、凭证或响应。

`FieldWriteGate` 先复核身份与具体动作权限，再原子取得写入位置，然后发送请求。同一账号、同一实体同时只允许一个操作；另一组件重新挂载也受此限制。已发出请求的完成处理继续维护记录，组件销毁后只停止页面回调。成功或明确的 4xx 拒绝清除该次记录；408、网络错误和 5xx 保留未知状态。迟到的旧完成结果不能清除后续操作。

未知状态下页面提供只读核对。若涉及分组，必须同时具备分组读取权限并成功读取分组；请求尚在进行时不能人工清除。读取成功后由操作者核对结果，再显式确认；不会自动重放原命令。读取开始、结束和确认时使用同一状态版本，其他操作引起版本变化也会保守地要求重新核对。账号或实体不同的记录互不阻塞。

列表、分组和编辑详情统一使用 `field-queries.ts`：读取前后请求 `/auth/me`，核对账号、角色及动作权限；传递取消信号并禁用缓存。字段记录检查实体、ID、键、状态和版本；列表检查页码、条数、总数与重复 ID；分组检查完整实体/键目标。这里仅检查读取目标和一致性，并未对整个 VO 的每个属性重新建模或投影。后端仍是最终授权依据，客户端复核不能阻止最后一次检查之后发生的授权变化。

恢复记录只在当前标签页内存中生效，刷新页面、关闭浏览器后丢失，不提供跨标签页或跨设备恢复，也没有增加服务端幂等键或乐观锁。SSR 不创建共享的账号恢复记录。React 的实际 hydration、浏览器切换路由与网络中断仍需浏览器验收。

验证入口：`pnpm test:admin-fields` 覆盖写入门禁、组件重挂载、身份/实体隔离、迟到结果、只读核对版本和异常读取。请求替身与同步 SSR 测试不等同于浏览器验收。独立 `pnpm test:admin-authorization-http` 另将生产字段/分组读取器连接到编译 Nest 和 PostgreSQL，流程见[管理授权真实 HTTP](admin-authorization-live-http.md)；它不测试实际 React 页面。
