# 管理端图片选择与上传生命周期

日期：2026-11-03。沿用 OpenAPI 1.50.2 / 143 操作和已确认的图片上传、扫描、资产归属与数据范围规则，没有新增业务接口、依赖或数据库迁移。用于文章封面、全局雪场封面和媒体库选择；雪场相册原有上传流程继续使用其自身的表单授权校验。

## 修复与边界

原媒体库直接使用泛型响应，畸形 items 或 null 图片可能在弹窗渲染时抛异常；上传响应还可能把额外字段留在前端状态，错误消息直接回显原始 Error 文本。四项回归先对旧代码复现失败，现由本端模型校验列表分页、记录、编号、日期、上传人、大小字符串和五类引用计数，并显式构造所需 VO。重复记录、非 ready 的列表结果、错误页码/大小/hasNext 等拒绝进入图片网格，保留错误和手动重试入口。

AssetId 保留十进制字符串，不把 int8 转为 Number；签名 URL 原文保留，仅允许无用户名/密码的 HTTP(S) 地址，拒绝脚本协议。合法 null URL 可显示为不可选图片；上传返回只保留图片控件需要的五个字段。读取明确 no-store，避免复用失效的资源信息。只有本端 AssetPickerError 使用本地错误文本，403/404显示对应提示，其他异常使用通用核对提示，不展示服务端、网络或存储原始错误。

新增本端 AssetPickerRun，只属于一个挂载的选择器。请求前后通过既有 /auth/me 校验当前 Cookie 身份、管理入口和相应读取/上传 grant，与发起时的账号、角色、权限和商家关联快照比较。失败不执行上传或不应用已返回结果，不按 merchant 角色键决定能力。媒体列表和选中记录各自有独立实例，取消列表不影响其他组件；选择仍需重新读取当前 ready 详情。

封面内部组件和媒体弹窗按身份快照隔离；身份变化不继续展示旧弹窗。组件销毁时取消本实例请求，代次检查阻止旧成功、错误和 finally 改写新状态；重新激活也不能接收旧代结果。封面上传同步门禁继续防止重复点击，回写前检查当前字段值和 disabled；期间被替换或禁止编辑时不覆盖新值。上传完成前父表单仍按原 busy 门禁阻止保存，销毁时释放本次 busy 状态。

这些检查不替代后端资产归属、当前授权和数据范围判定。/auth/me 无有效数据范围或会话 ID 投影，客户端不能据此证明同账号换会话或同 grants 下的范围变更；具体资产读取/关联仍由后端过滤。前后预检与上传不是同一事务，不能宣称消除检查之后到请求/回调之间的一切竞争。取消也不保证回滚已抵达服务器的上传，可能留下未关联资产；没有新增上传幂等键、自动删除或自动重放。网络结果不明时须人工核对媒体状态，本轮未新增跨刷新上传台账。

## 验证

四项旧问题先失败后修复；新增34项，与既有101项媒体测试合计135项通过，纳入既有 test:admin-assets 和完整 check。新增生命周期测试使用真实 AssetPickerRun 与可控请求 Promise，验证前后身份、权限/角色/商家变化、取消、销毁/重激活、迟到错误/成功/finally和无自动重发。模型测试验证畸形分页、null、精确大编号、签名 URL、额外字段裁剪及安全错误；现有控件/网格 SSR 与表单专项保持。

已查阅本仓安装 Next.js 16.3.5 的 Vitest 文档，测试边界为同步组件 SSR、控制器和请求替身，不能代替真实 React 挂载/Modal、浏览器文件选择、Cookie、扫描器/S3 或完整表单业务验收。完整三仓冻结安装、检查及构建/导出结果见阶段交付记录。Docker 按用户决定保持原状；没有重试此前被自动审批拒绝的服务启动。
