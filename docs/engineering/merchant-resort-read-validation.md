# 商家雪场完整读取、复审与生命周期

日期：2026-11-03。负责人：Web。契约沿用 OpenAPI 1.51.1 / 143 操作，不新增业务接口或迁移。结果见[本仓验证摘要](../validation/resort-reads-20261103.json)。

列表、详情、创建/编辑表单及保存/提交审核回执均按声明投影，从 unknown 检查完整 MerchantResortVO：编号、名称与地区、十进制坐标/评分、精确资产字符串 ID、HTTP(S) 图片链接、相册、标签、价格、营业状态、雪况及时间、介绍、设施、扩展 JSON、审核状态及更新时间。拒绝重复图片/标签和非法 JSON；扩展字段复制后保留 0、false、空字符串及 null，不将 VO 之外的联系资料等附加属性传入页面。分页检查请求页码、条数、重复项、状态及 hasNext，允许后续空页。

有效字段目录按当前生成契约检查必需项；可选元数据只有出现时才投影并验证，不伪造为必填。字段键、定义 ID、分组去重，匹配实体及归属；禁止既不可读也不可写的条目。JSON 默认值与校验规则深复制。字段目录比较先规范投影，避免属性顺序导致误判。表单字典复用本端完整字典解析器，要求类型吻合且启用；展开选项采用迭代，去重请求并复用标签字典。

读取前后复核完整身份，包含账号、商家资料、角色和权限；本地身份先校验。详情 404 仍复核身份，未知结果恢复明确提示 404 不能证明停用成功。前后身份读取不提供跨请求原子快照，后端范围和字段策略始终是授权依据。

列表、编辑表单在 hidden/pagehide 时取消查询并清空数据、字典、图片关联和预览；上传同时取消，旧上传的 finally 不解除新请求的同步锁。首次在后台打开显示暂停状态，返回后显式重新读取。写入门禁校验本地身份，并在异步准备完成后再次争用共享恢复账本；两个挂载组件不能同时发出同账号写入。已发出但结果未知的请求仍留在原账本，需要读取并人工核对，不自动重发。核对代次隔离旧 finally，隐藏时不能确认旧结果。

真实接口验证使用生产客户端、表单准备器及命令方法，覆盖草稿创建、提交审核、管理员发布、已发布资料编辑后 pending_review 且公开查询隐藏、复审发布、管理员下架、商家再次送审、本人软删除及另一商家不可见。另在真实详情响应后撤销 grant，结束身份复核拒绝交付该结果。后端核对最终物理行、商家归属、八条事件和八条成功审计。

现有雪场 DTO 没有客户端版本前置条件或创建幂等键，预读业务指纹不能提供对应并发保证。Node Cookie 适配及模拟 Hooks/EventTarget 不计浏览器/BFCache/设备验收；Outbox 持久化不计 Kafka 投递；不包含图片上传/签名存储或真实 AI 供应商。D-49、D-50、D-09 保持未实施，整体项目未完成。
