## 页面数据与交互

`features/resorts/resort-query.ts` 负责 URL 输入、白名单校验、查询编码、加载状态和分页链接；`resort-directory.tsx` 渲染表单、卡片和状态。`app/resorts/page.tsx` 等待 searchParams 后装配结果。响应、营业状态和排序联合类型来自本仓 OpenAPI 生成代码。

筛选支持名称/地区关键词、省/市/区县、非负整数票价区间、最低评分、营业状态、参考纬度/经度、四种排序与方向。坐标成对且可为 0，距离排序要求坐标；评分 0–5，价格上下界有序，分页 offset 在 int4 边界内。非法输入展示字段提示且不请求后端。卡片展示完整地区、评分、票价、适配标签和可空直线距离；0 米照常显示，缺少封面显示“雪场图片待更新”。

原生 GET 表单应用条件时从第一页开始；上一页/下一页、失败重试链接保留所有条件及重复 fitTags，重复标签去重但不拼成逗号字符串。空的后续页仍提供返回上一页。关键词与标签按 URLSearchParams 编码，页面不转发未知键、商家身份或管理发布状态。服务端 total 作为总数，不能由当前页条数推算。

2026-11-03按当前代码复核：公开标签目录已按确认接入 `GET /resorts/fit-tags`，与雪场列表独立读取、no-store；表单以checkbox多选，并以重复fitTags参数提交。目录失败仍展示已选项，目录中缺少的既有选项按原值保留，空目录提供提示；其余筛选可独立使用。本段替代此前“待确认/仅隐藏字段”说明，下方测试数量保留历史阶段范围，最新复验以README为准。

## 配置错误与浏览器证据

真实浏览器发现 `NEXT_PUBLIC_WEB_API_BASE_URL` 缺失时，惰性请求初始化同步抛错，导致 SiteConfigProvider 的 effect 逃逸并出现整页错误。官网/Admin 的 apiRequest 现为 async：地址验证或客户端构造失败均成为 rejected Promise，进入各功能既有错误/重试状态；失败初始化可重试，Cookie/CSRF、信号和请求选项保留。

在原 3010 开发进程实际检查了：缺少地址配置时页面仍显示表单、会话与平台信息失败提示；无坐标距离排序显示具体校验消息；区县、价格 0–300、坐标 0/0 和排序方向提交及重试后保留。332 像素窄屏截图复核后，为导航链接增加不换行，并隐藏窄屏装饰性“雪场指南”文本，主导航保留。当前进程没有 API 地址，成功数据态的浏览器全链路仍未验证；没有修改其环境或重启原进程。
