# 官网首页内容接入

## 2026-11-03 响应投影与故障隔离

沿用OpenAPI1.50.2/143操作及首页三个公开查询，没有新增接口、依赖或数据库迁移。直接信任泛型响应会让空items、异常评分或缺失作者在渲染时导致整页失败；五项回归先对旧实现复现失败，现由本端featured-response.ts按公开VO构造新对象，丢弃未知额外字段，单个内容区响应异常仅将该区标为unavailable。

校验首页最多三项、编号和重复记录、地区与分类/标签结构、有限评分及计数、金额字符串、日期、已发布动态及最多九张图。动态字段只接受已有VO的标量/字符串数组/null；不会将任意嵌套对象传给页面。评分/价格/图片等可空值、0元价格、签名图片URL及历史头像字符串保留兼容；封面路径须能用于现有图片组件，签名查询字符串不重写。仅读取首页items投影，不声称校验未消费的分页元数据。

三个请求仍并发且cache:no-store，明确credentials:omit、skipAuthRefresh:true。服务端只取公开内容，不转发浏览器身份，也不因公开401调用CSRF/refresh。文章收藏仍由浏览器已有会话与收藏组件独立读取本人状态，未更改凭证协议。每个读取有10秒超时，覆盖等待响应和未结束的正文；超时取消对应请求并降级。三个读取均结束后再渲染，没有改为逐区流式页面或新增自动刷新。

新增两个测试文件40项，与原有首页6项合计三文件46项，通过本端lint与typecheck。覆盖畸形列表/卡片、额外字段投影、合法空值与签名URL、独立失败和SSR可渲染。五项使用真实Node HTTP与合成API，验证既有信封解包、匿名公开读取、公开401不刷新、异常JSON隔离、下一次读取恢复和10秒正文超时的连接取消；其中恢复与超时分别在独立用例验证。完整三仓冻结安装、check及构建结果见本阶段记录和各仓README。

验证边界：Node HTTP合成API不等于真实Nest/PostgreSQL、Next async Server Component、浏览器hydration或真机验收。继续使用connection()保持请求时渲染；查阅安装的next@16.3.5文档connection.md和06-fetching-data.md。没有重试此前被自动审批拒绝的生产/Expo开发服务启动；Docker按用户决定不重启。登录限流D-51仅整理待确认建议，不混入本次首页实现。

## 历史实施证据

2026-10-30 D-36：首页文章增加浏览器会话与按当前账号加载的收藏交互，服务端仍只取公开正文。当前 OpenAPI 1.37.0；见 [文章收藏](article-favorites.md)。下文“没有前端自动刷新”为历史首页阶段说明，文章收藏区域现已在导航/恢复焦点与写后重新读取。

2026-10-29；WEB-01 消费既有 OpenAPI 1.28.0，不新增后端接口或跨仓依赖。

首页通过三个公开查询并发读取内容：

| 内容区   | API                                                           | 选择与展示                                                               |
| -------- | ------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 雪场     | `GET /resorts?page=1&pageSize=3&sortBy=rating&sortOrder=desc` | 评分优先，展示封面、地区、评分、票价、标签和营业状态                     |
| 滑雪知识 | `GET /articles?page=1&pageSize=3`                             | 现有发布时间倒序，展示封面、分类、标题、摘要、作者及发布时间             |
| 雪友动态 | `GET /dynamics?limit=3`                                       | 现有公开游标首批，展示作者、正文摘要、图片、关联雪场、互动计数及创建时间 |

“精选”是上述公开排序的前三项，不引入未约定的人工推荐字段。雪场卡片 VO 无更新时间，首页不伪造此字段。图片为空时沿用现有风景占位；内容摘要以 React 文本渲染，不解释为 HTML。

`src/app/page.tsx` 在请求时调用 Next.js `connection()`，然后读取三个 API；避免构建时缺少 API 配置或服务故障导致失败状态被静态固化。所有读取显式 `cache: no-store`，仅经本端 API transport；不转发浏览器凭证、不调用数据库或模型。部署仍须按 README 注入正确的公开 API 地址。

`features/home/featured-content.ts` 区分 ready（可为空）和 unavailable；单个读取失败不丢弃其他成功内容，页面保留该区目录入口，原始错误不展示。三个读取并发，但本页当前等待所有读取完成后渲染，没有逐区流式加载或前端自动刷新。刷新页面重新查询。

`HomePageView` 是同步展示组件；文章与动态卡片提取到本应用的 `features/public-content`，同时供列表和首页使用，未移到跨应用公共包。样式沿用 CSS Modules，首页内卡片网格取消目录页面的额外外边距。

## 验证

`pnpm test:web-home` 已进入 `pnpm check` 和既有 CI。6 项测试覆盖公开查询参数、并发及独立失败、成功 VO/日期/详情链接、文本转义、空数据和全部服务失败。测试使用替身 API 和 React 静态标记渲染同步组件，不能证明 async Server Component、浏览器 hydration 或真实数据库业务流程。

本轮 Web 全量 check 61 项测试与双应用 production build 通过；最终首页构建表为 `ƒ /`。在既有 3010 开发服务浏览器观察到三个内容区的失败提示及可用目录链接；成功/部分失败/空状态为单元测试证据，真实 API 成功态及桌面/设备视觉验收仍待完成。尝试启动独立 3000 production 服务进行故障恢复验收时被自动审批审查拒绝，未提供原因，未换命令绕过；临时 fixture 进程已停止。
