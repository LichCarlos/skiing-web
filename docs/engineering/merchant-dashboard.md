# 商家工作台

2026-10-31，落实已定版 ADM-02 `/admin/merchant`。页面复用现有商家雪场与收益 API，没有增加全局工作台汇总接口或数据库表。OpenAPI 1.40.0 补齐既有商家雪场响应类型；Web/App 各自在仓内生成类型。

## 页面与请求

- 雪场面板：按状态筛选，读取第一页 5 条，展示服务端 `total`、最近更新的雪场名称、地区、发布状态和更新时间。不能以预览条数推算总数或各状态数量。
- 收益面板：默认最近 30 个 UTC+8 业务日期，支持日期区间和可选雪场 ID；展示总金额、每日相对峰值趋势、最近 5 条记录，并链接到完整明细。金额复用字符串/BigInt 格式化，不转浮点数。
- 请求为 `GET /merchant/resorts?page=1&pageSize=5&status?`、`GET /merchant/revenue` 和 `GET /merchant/revenue/summary`。收益列表/汇总传递相同日期、雪场和分页筛选，列表默认按既有服务端规则排序。

页面与导航共用入口规则：`management:portal:enter` + `merchant:dashboard:read`。雪场和收益分别需要 `resort:merchant:list`、`revenue:merchant:list`，缺一项只阻止对应请求，不根据 RoleKey 判断商家。没有有效商家资料时展示绑定提示；客户端不提交 merchantId/userId。

后台 API 继续分别执行既有动作权限、有效商家身份和数据范围校验。工作台入口 grant 本身不授予数据读取权，也不替代服务端安全检查。多角色范围冲突由后端拒绝，页面展示授权错误。

## 状态与组件

`dashboard-model.ts` 负责输入校验、查询装配、请求取消和错误归一；`dashboard-sections.tsx` 渲染两个面板，复用已有 RevenueSummary；`merchant-dashboard.tsx` 绑定会话、筛选草稿和查询生命周期。没有新依赖。

两个面板各有加载、无权限、失败、空和成功状态；雪场失败后仍能显示成功的收益，反之亦然。收益列表与汇总作为一组成功后才展示，防止混合部分结果。错误展示可公开的 traceId，不输出服务端原始诊断。

账号、有效商家或 grants 变化会卸载旧结果；提交筛选和刷新也重建结果组件并取消旧请求。即使传输层在取消后才返回，仍拒绝发布旧结果。日期必须是真实日历日期且正序，雪场 ID 是正 int4。布局可换行，表格支持横向滚动，趋势包含日期/金额文本与原生 meter。

## 权限目录升级

新增 `menu:merchant:dashboard` 和 `merchant:dashboard:read`，管理员可在现有授权页配置。seed 为新建的商家角色模板加入这两项，也为系统管理员补齐目录权限；重复 seed 不改写既有非管理员角色授权。已有商家模板或自定义角色须由 system_admin 显式配置入口/工作台及所需数据查询 grants，不能以一次 seed 自动扩大现有权限。

系统管理员通常没有 MerchantProfile；进入此页时同样提示绑定资料，不绕过商家归属读取全局经营数据。全局工作台 API-M01 的精确汇总协议仍未定版。
