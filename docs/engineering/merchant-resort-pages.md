## 页面与契约修复

商家列表使用生成的 MerchantResortPageVO/VO，不再手写列表响应；筛选仅发送 page/pageSize/status，不发送账号、商家或范围。状态切换回第一页，后续空页可返回第一页，加载和错误清除旧数据。RequestLane 取消同时抑制迟到成功、错误及 finally。

商家表单独立于原管理员编辑实现。原实现按 fitTagValues 读取详情，而现有 VO 返回 fitTags，造成标签不能正确回填；现显式映射，标签修改与清空均发送 fitTagValues。评分仅展示；DTO 白名单不携带 merchantId、status、rating、ratingCount、VO 字段或外部图片 URL。可空坐标和文本显式清空，省市区县、营业信息、雪道、设施、官网、介绍沿用现有约束。

动态字段根据当前有效 schema 初始化：可读值正常显示，只读字段不进入写入 DTO，编辑已有记录时不初始化不可读字段的默认值。仅提交可写且改变的字段，保留未编辑的仅可写值及隐藏历史字段；显式 null 可以清除。新增草稿按现有默认值初始化。字段所需字典与雪场、标签、字段目录全部成功后才开放保存；只读选择字段不请求其选项目录。

表单仍调用既有管理字典接口，因此账号须有现行字典读取权限。目录拒绝会明确报错并关闭保存，不自动给业务身份补权，不改成未确认的公开目录。全局管理员雪场字段策略及公开标签目录仍按既有待定版方案处理。

## 身份与动作

页面工作区按账号、有效商家关联、grants、角色键、目标和动作隔离；商家身份来自 currentUser.merchant，不依赖 merchant 角色名。入口需要管理入口、商家资料及 list grant，新建/编辑另需对应 create/update。恢复中、匿名、读取失败或关联消失均不读取私有内容。每次读取与正式写入前复核 /auth/me；精确数据范围由后端决定，不因前端缺少 scope 投影推断更宽范围。

保存前重新读取原雪场和有效字段目录。比较更新时间、状态、正文、标签、扩展字段及图片 ID/顺序，忽略短时签名 URL 变化；资料或策略变化要求刷新重新操作。客户端预读与服务器写入之间仍有并发窗口，既有接口没有客户端 expectedVersion，不能把此检查描述为乐观锁。

保存和提交审核分开。published 保存继续按服务端规则转 pending_review 并从公开列表隐藏；提交审核只允许 draft/offline，并检查当前表单无未保存修改。确认后再次读取原目标；命令仍是 PATCH /merchant/resorts/:id/submit-review 与空对象。列表停用先确认、复读原目标，使用既有无 body 的 DELETE 软停用。

编辑路由与路由授权统一校验规范正 int4，拒绝 0、前导零、科学计数和超界编号。功能域维护 routes.ts，经 config/routes.ts 聚合。

## 图片与恢复

图片仅通过本人上传流程加入表单，复用现有 JPEG/PNG/WebP、10 MiB 和 ready 扫描校验，不借用全局媒体库获取其他账号图片。同步上传锁与写锁互斥，上传前后核对身份；取消或换工作区后响应不写回新表单。相册上限30张、去重、支持上下移动，数组顺序即服务端 SortOrder；资产 ID 始终为 bigint 十进制字符串。封面和相册预览来自现有短时 URL，重新读取可刷新预览。

操作在异步校验前领取同步锁，准备完成后复核精确动作 grant。浏览器内存台账按账号记录动作和目标（新建记录名称），进行中请求跨组件重挂载仍阻止重复；网络错误、408 和 5xx 作为结果未知，不自动重放。读取目标并刷新后须人工核对；404 不证明停用成功，第一页候选列表未找到也不证明创建失败。核对期间新操作改变台账版本则旧核对失效；进行中不可解除。编辑页目标已不存在时可回列表完成核对。

台账不跨浏览器刷新、标签页或设备，没有服务端创建幂等键。上传后未保存的图片可能保留为未关联资产；本阶段未增加自动删除或垃圾回收协议。
