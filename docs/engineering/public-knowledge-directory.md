# 官网知识目录的筛选与失败恢复

2026-11-03续验：现行OpenAPI1.50.2/143操作，[公开列表边界](public-directory-validation.md)补齐文章/分类独立运行时投影、分页及重复项校验、匿名无刷新读取和10秒正文取消；收藏仍由既有客户端会话负责。下方数字为历史证据。

日期：2026-10-31。对应 WEB-06、API-K01；沿用本仓 OpenAPI 1.41.0 生成的文章与分类 VO。查阅当前安装 Next.js 16.3.5 的 page 与 Fetching Data 文档，页面等待 Promise searchParams，再通过后端 API 读取，不直连数据库。

## 页面与数据流

`app/knowledge/page.tsx` 负责读取筛选并装配页面；`features/knowledge/knowledge-query.ts` 负责输入校验、查询编码、数据加载和分页链接；`knowledge-directory.tsx` 负责同步视图。关键词/分类最长 100 字符，page 必须为正安全整数，偏移不得超过 int4；非法条件保留表单并给出修复提示，不请求 API。

列表与分类以 Promise.allSettled 独立读取，并使用 cache: no-store。分类失败时保留成功文章和原分类值，允许搜索、清除或重试；文章失败时保留成功分类。两者失败也保留可用表单。原生 GET 筛选不携带旧页码，从第一页开始；分页和重试沿用已编码的完整关键词/分类，空的后续页也能返回上一页。

卡片、分类文本与筛选值由 React 转义；total 来自服务端，不由当前页条数推算。文章收藏继续交给既有 ArticleFavorites 和 Cookie 会话按当前账号核对，不把 SSR 游客响应当作已登录收藏状态。

## 验证

15 项 loader/SSR 测试覆盖非法页码/溢出、长度边界、URL 编码、独立失败、当前分类保留、分页和重试、空后续页及文本转义，已加入独立仓库 check。真实后端 HTTP/PostgreSQL 另覆盖特殊字符字面查询和稳定分页。

在原 3010 开发进程的真实浏览器验证了越界页码提示，以及重新筛选从第一页开始、保留关键词/分类、独立错误提示和重试链接。原进程缺少 API 地址，未改其环境或重启；成功数据浏览器工作流仍未验收。截图检查了当前桌面视口及提示区域的对齐，不能据此声称所有视口或无障碍验收通过。
