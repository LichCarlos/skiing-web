## 页面与授权

列表将输入关键词与已提交条件分开，搜索/清空/状态切换重置页码；表格固定每页20条，重试保留条件，后续空页提供返回入口。读取前核对 `/auth/me`，请求使用 no-store；RequestLane 取消前次读取，迟到结果不覆盖新页面。加载、失败、空结果独立展示，表格支持水平滚动。

工作区等待会话恢复，按账号、角色键、grants及目标重建。项目知识沿用仅受保护 system_admin 的既有服务端限制，前端检查唯一 system_admin 角色及管理入口、精确动作权限；不将此规则扩展到商家等其他业务功能。列表/详情要求 list，编辑另要求 update；新建只要求 create，不额外查询列表。客户端没有 SystemRoleCode 投影，受保护身份仍由后端独立核实。

创建确认后展示记录编号与标题，仅向有相应权限的账号展示列表/编辑链接，提供“继续新建”。加载失败隐藏旧表单和旧状态；写入失败保留输入。刷新资料提示会替换输入。编辑地址与路由授权均限定规范正 int4 ID。

## 写入与版本

表单 DTO 白名单为 title、content、category、sourceUrl；编辑增加加载时的 version，不接收客户端 status、作者、发布时间或其他字段。空来源链接转 null；非空来源仅接受不含 userinfo 的 HTTP(S) 地址，最终文本和敏感信息校验仍由后端执行。

同步写锁在异步表单校验之前取得。编辑提交前重新读取目标，若版本与原表单不符即停止；正式 PATCH 继续使用原始 version，不能用新版本掩盖过期输入。后端现有条件更新提供服务端乐观并发校验。写入之前再次读取身份，校验账号、角色和精确动作权限。

发布、撤回和软删除在列表中使用独立确认命令，不隐含保存表单。命令前重读目标并核对展示版本和状态；现有命令不接收客户端 expectedVersion，因此预读与提交间仍可能变化，不能宣称客户端命令具备版本前置条件。后端继续在事务内验证授权、状态和版本并原子写入审计/Outbox。已发布内容编辑保持发布；RAG消费者异步读取权威状态，接口成功不证明向量重建已经结束。

## 未确认结果

浏览器内存台账按账号记录进行中或未知的动作，仅保留目标编号或创建标题。网络错误、408、5xx及成功响应形态异常保留记录；明确成功或其他确定4xx解除记录。页面卸载取消请求并隔离回调；旧客户端请求未结束时不允许人工解除阻塞。

请求结束后，操作员读取目标并刷新页面，再人工确认。台账变化会使旧核对失效。创建搜索仅提供标题候选，404可能表示失去读取范围，均不能据此证明写入或删除成功。仅有创建权限但出现未知结果时，需要恢复读取权限后核对，不偷偷调用未获准列表接口。明确成功后的回调错误不将成功重新归为未知。

台账不跨整页刷新、标签页、关闭页面或设备；取消fetch不证明服务端事务已终止。没有为既有接口增加创建幂等键，不提供跨设备或 exactly-once 保证。
