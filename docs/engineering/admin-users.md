## 页面与数据契约

`/admin/system/users` 使用 `ManagedUserPageVO`，支持关键词、状态、固定每页 20 条、失败重试及空页返回。展示账号、昵称、角色及停用标记、商家业务资料、账号状态和创建时间。创建使用 `CreateManagedUserDto`，账号 trim 后转小写、昵称 trim；账号和昵称最多 50 个 Unicode 字符。密码保持原样并按 8–72 UTF-8 字节校验，成功、关闭或未知结果时清空密码表单。

角色选择按当前角色查询权限逐页读取活动目录，每页 100 条，直到 hasNext 为 false。目录分页异常、重复编号或后续页失败时不开放部分目录。没有 `system:role:list` 但有账号创建权限时，仍可创建使用默认注册角色的账号；未挂载角色控件时显式按空数组构造 DTO。服务器决定默认注册角色，页面不猜测 `user` 或 `merchant` 键。

分配角色前读取最新账号详情。PUT 完整替换 roleIds，清空即移除全部角色；停用、不可见或不可授予的既有角色显式展示，需人工移除，不自动丢弃。仅 system_admin 可独立授予 system_admin，后端通过受保护身份最终验证。角色目录查询不是跨页一致性快照，角色 PUT 也没有版本字段；并发授权结果和最后管理员保护由后端事务裁决。

状态修改前重读目标并检查与展示状态一致，随后 PATCH。修改本人角色或状态成功后重新恢复会话。管理员创建账号时可以直接设置初始密码，账号已有本人改密能力；管理员重置既有账号密码的精确 API 尚未定版，本阶段不新增路由。

`/admin/system/users/[id]` 使用 `ManagedUserVO`，展示脱敏详情、加载、错误和刷新。路由服务端等待 params，仅接受规范正 int4 编号；详情组件按目标编号和身份快照隔离。读取身份和目标均 no-store，详情响应编号必须匹配请求目标。

## 权限、取消与写入结果

入口需要 management:portal:enter 和 system:user:list；创建、角色替换、状态修改分别需要对应动作 grant。商家是业务资料及授权组合，自定义角色按权限工作。服务端独立验证 user 数据范围及事务授权，前端控件不能替代授权。

列表、编辑准备和恢复分别使用 RequestLane；AbortSignal 及请求所有权屏蔽迟到回调，取消后不继续启动目标或下一页请求。身份、权限集合、角色集合和商家资料变化会重挂载工作区。查询与写前重新读取 `/auth/me`，快照变化则提示重新读取身份。

AccountWriteGate 在异步表单校验前同步锁定，校验完成后重读身份，确认入口与动作权限，再执行一次写入。未知的网络、408 或 5xx 结果会阻止后续写入，不自动重试；明确的 4xx 拒绝（408 除外）释放当前操作标记。卸载后的结果不触发 UI 回调，明确成功或拒绝仍仅清除自身操作标记。

浏览器内存台账按操作者及操作 token 保存目标描述，仅含操作、目标账号或编号，不含密码或请求体。导航或守卫重挂载后先读取对应目标并刷新列表，再人工核对继续。创建查询按规范化账号精确匹配；未找到可见账号不代表创建失败，分页未定位、目标不可见或读取失败不放开自动恢复。台账不支持完整刷新、跨标签页或跨设备恢复，不替代服务端幂等或并发控制。
