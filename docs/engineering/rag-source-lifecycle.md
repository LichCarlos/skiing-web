# RAG 来源读取与命令核对

2026-11-03 RAG来源真实HTTP续验：当前生产读取器、命令与恢复控制器已接入实际编译Nest/临时PostgreSQL，新增六项RAG联调，管理全套21项及后置持久核对通过，见[真实HTTP范围](rag-source-live-http.md)。实际浏览器/React/BFCache、完整刷新恢复和模型索引完成仍需单独验收。

负责人：Web Admin。范围：已确认 D-46 / ADM-18 / API-AI-03。当前三仓 OpenAPI 1.51.1；沿用来源列表、详情、重建和启停协议，未增加接口、权限或数据库迁移。补丁版本同步了另行确认的 D-52 会话引用声明。

列表与详情通过 `rag-queries.ts` 读取，响应由 `rag-model.ts` 投影为固定的来源元数据。校验 ID、控制版本、类型、状态、布尔值、1024 维、分块数量、按 Unicode 码点排序且不重复的模型名称、ISO 时间、失败标记及分页总数；丢弃正文、Metadata、向量和供应商错误等额外属性。每次读取前后均以相同 AbortSignal 和 no-store 重新读取 `/auth/me`，确认账号、角色、授权仍与页面快照一致。读取失败、页面隐藏和离开时清空旧数据；返回页面后由用户显式刷新。

提交前校验并裁剪原因，重新读取目标，核对来源键、类型、ID、人工开关与 controlVersion，再复核动作权限。命令仍携带原 expectedVersion，由服务端事务、版本检查、审计及 Outbox 保证写入规则。客户端校验命令响应中的目标、版本增量、事件 UUID、pending/disabled 状态，以及停用后的分块清空；匹配版本的同状态开关允许无事件、无版本变化。202 只表示受理，索引最终结果需刷新核对。

`RagCommandSession` 同步锁住一次提交，阻止重复点击；`RagRecoveryLedger` 在发出命令前记录账号、目标、原版本、动作及在途状态。记录不包含原因、正文、凭证或供应商数据。同一标签页内，记录跨页面卸载、重挂载和授权快照变化保留；其他账号和其他目标隔离。SSR 不共享单例。隐藏、pagehide 和卸载会取消请求；迟到响应不能恢复来源或清除记录，旧 effect 清理也不能终止新的激活。

恢复提示通过 useSyncExternalStore 的服务端快照边界呈现：SSR 和 hydration 初始快照统一为 0，订阅建立后才显示浏览器内已有记录，避免首次 HTML 与恢复状态不同。新增静态渲染回归证明该接线；真实浏览器 hydration 和 BFCache 仍需另验。

发出命令后的网络失败、异常响应、最终身份复核失败或页面离开均视为待核对，不重放命令。即使客户端收到了 4xx，也先要求读取当前状态。用户需等本地在途请求结束，再重新加载同一目标；读取期间记录版本不得变化，之后才能点击“已核对当前版本，允许后续操作”。读取本身不清除记录。来源当前版本相同，也不能证明旧 HTTP 请求没有在服务端执行；后续命令继续受 expectedVersion 约束，两条使用相同原版本的非空操作不能同时成功。该确认表示用户检查了当前状态，不是对历史执行结果的归因或服务器幂等凭证。

恢复记录仅保存在浏览器标签页内存，不跨完整刷新、浏览器关闭、多标签页、设备或部署。完整刷新后必须重新读取服务端状态；需要确认历史命令结果时核对服务端审计和 Outbox。没有新建服务端结果查询或客户端持久化协议，也不宣称端到端 exactly-once。

专项测试覆盖响应白名单、过滤和分页边界、读取前后身份变化、提交前目标/版本冲突、命令响应、同步锁、并发组件、在途核对拒绝、跨重挂载、隐藏/卸载后的迟到结果、旧 cleanup、账号/目标隔离及真实页面 SSR 门禁。完整三仓结果见[本轮摘要](../validation/rag-source-lifecycle-20261103.json)。这些是运行时模型与 SSR 测试，不能证明当前源码在真实浏览器中完成交互、BFCache 恢复或视觉验收；历史浏览器记录不替代本次复验。
