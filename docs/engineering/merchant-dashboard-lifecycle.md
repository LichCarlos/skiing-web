# 商家经营概览读取与授权生命周期

日期：2026-11-03。负责人：Web。页面 ADM-02 `/admin/merchant`，复用 API-R02/API-R03，不新增接口、DTO、数据库迁移或权限。

经营概览此前直接使用服务端类型断言；异常金额会进入 BigInt 格式化，额外响应字段留在页面状态，读取期间的身份变化也没有最终核对。现在雪场响应仅保留展示使用的 ID、名称、地区、状态和更新时间，收益响应逐层投影现有 VO；校验分页、正 int4、重复记录、日期、精确金额字符串及已应用筛选。雪场状态不匹配、收益日期或雪场不匹配均关闭对应面板。独立面板保留局部失败能力，不将最近五项推算成全量汇总。

`readMerchantDashboard` 在发出业务查询前后各读取一次 `/auth/me`，比较账号、用户 ID、商家关联、角色键集合和权限集合。只有管理入口、商家工作台权限及有效商家关联满足时才发起读取；雪场与收益仍按各自 grant 独立查询。角色名称可以配置，没有硬编码商家角色。全部请求使用 `no-store` 和同一个取消信号，不发送 userId 或 merchantId。

`/auth/me` 沿用既有 `account:profile:read` 要求。联调角色显式配置该权限；页面不自动给商家或任意角色补权，也没有修改认证协议。

页面子树按上述身份重挂载，查询切换取消旧读。`createMerchantDashboardRun` 负责取消、隐藏时清空、销毁及迟到响应隔离；`visibilitychange` 和 `pagehide` 接入清空。重新可见后由用户显式读取，不自动恢复旧收益。另提供“重新读取身份”，先清空当前结果，再交由现有会话控制器恢复身份，以便账号、商家关联或权限变化后恢复查询。SSR 只输出表单和读取提示，不读取私有数据。

日期范围继续使用既有收益查询规则，最多 367 个日期。金额保持十进制字符串；图表相对值转换发生在精确整数计算后。投影不改变后端授权，身份核对不是授权租约；雪场列表、收益列表与收益汇总仍是三个独立数据库快照，不能宣称原子一致。相同角色键下的数据范围变化不由 CurrentUserVO 完整表达，服务端仍须对每个请求独立授权。

验证入口：`pnpm test:merchant-dashboard` 和 `pnpm test:admin-authorization-http`。后者必须指向新建的专用 PostgreSQL 集群及编译后 Nest 服务，不能使用业务库。新增四条真实 HTTP 场景验证本人收益 123.45 与另一商家 678.90 隔离、雪场展示白名单、外部雪场收益拒绝、独立面板权限、实际读取期撤权；后置夹具核对原始两条收益记录、返回归属、拒绝审计和会话撤销。凭据仅在验证进程内存中传递。

专项与全量结果、产物及日志摘要见[本轮验证记录](../validation/merchant-dashboard-20261103.json)。页面测试使用同步 SSR，生命周期测试使用控制器及请求替身，真实 HTTP 使用 Node Cookie transport；都不能代替浏览器可见性/BFCache、Secure/SameSite/CORS、设备或实际图片存储验收。本轮不重跑完整 Kafka 集成，当前 Windows Kafka 失败仍按既有诊断保留；Docker 未启动或重启。未定版 D-49/D-50/D-09 保持待决。
