# 权限目录读取与维护联调

日期：2026-11-03。负责人：Web 维护者。对应 ADM-09 / API-M04；沿用 OpenAPI 1.51.1 / 143 操作，不增加接口或数据库迁移。

`catalog-queries.ts` 集中读取完整权限树和单节点子树。读取前校验本地身份并查询 `/auth/me`，收到业务数据后校验与投影，结束时再次核对账号、商家、角色和 grants。目录节点显式保留生成 VO 字段，校验编号、父子关系、重复编号/键、类型、来源、状态、可见性、排序及可空文本。迭代遍历避免前端响应解析递归溢出；不凭前端常量推断新的业务权限。单节点详情允许根节点保留其实际 parentId，整棵目录树的根必须没有父节点。成功写入和注册表同步回执也需通过校验，异常成功响应进入原有未知结果核对。

工作区按账号、商家、有效角色和 grants 隔离。页面隐藏/pagehide 时取消列表和编辑读取，清空目录、编辑目标及表单，暂停写门禁；准备中的表单不能在隐藏后继续发送写入。已经发送但结果不明的操作保留原内存恢复记录，重新可见需手动刷新或核对，不重放写入。核对代次使旧请求的迟到完成无法解锁新操作。编辑准备另有同步锁，避免同一帧多次打开。

本地测试覆盖投影、结构异常、深树、身份变化、取消、隐藏和在途写入。生命周期使用模拟 Hook / EventTarget，不代表真实 React、浏览器/BFCache 验收。生产读取器和写门禁另与编译 Nest/PostgreSQL 联调：完整树/子树投影；通过可配置权限创建目录、菜单、按钮并更新菜单、停用按钮；有子节点的菜单不可删除；普通账号即使具有 update grant 也不能同步代码注册表；读取期间真正撤销查询 grant 后拒绝旧结果。

测试 Cookie jar 使用 Node 适配，没有启动 Next 服务。前后身份检查也不能把多次 HTTP 读取变成原子快照；服务端继续独立控制每次读取和事务授权。证据见[本仓报告](../validation/catalog-reads-20261103.json)与[后端说明](../../../backend/docs/engineering/permission-catalog-http-validation.md)。真实浏览器、设备、Kafka、供应商、容器、签名包和远程 CI 仍待验。D-49/D-50/D-09 保持待确认。
