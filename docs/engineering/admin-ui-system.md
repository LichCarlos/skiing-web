## 通用组件库如何选

| 组件库                                                                                    | 主要特点                                                         | 适合用途                     | 与本项目的关系                                             |
| ----------------------------------------------------------------------------------------- | ---------------------------------------------------------------- | ---------------------------- | ---------------------------------------------------------- |
| [Ant Design](https://ant.design/)                                                         | 表格、表单、树、日期、弹窗等后台控件齐全，中文生态成熟           | 业务复杂的管理后台           | 管理端已有依赖，继续作为主组件库                           |
| [shadcn/ui](https://ui.shadcn.com/)                                                       | 将组件源码放入项目，适合 Tailwind 与深度定制；组件代码需自行维护 | 官网、产品界面、个性化组件   | 本仓共享 UI 已有相关基础，可按真实需求扩展                 |
| [Mantine](https://mantine.dev/)                                                           | 组件和 hooks 丰富，表单、日期等有配套方案                        | 新建 React 应用、工具站      | 可用于新项目，本管理端无须再混入完整组件体系               |
| [MUI](https://mui.com/material-ui/)                                                       | Material Design 体系成熟，主题和无障碍支持完善                   | 偏 Material 风格的产品和后台 | 另一种整体选型；部分高级 Data Grid 功能需要商业许可        |
| [Radix Primitives](https://www.radix-ui.com/primitives) / [Base UI](https://base-ui.com/) | 提供无样式或低样式的行为基础，便于自定义外观，需自行补齐视觉系统 | 自建组件库、特殊交互         | 公共 Button 已基于 Base UI；不替代后台的整套表格与业务表单 |
| [Arco Design](https://arco.design/react/docs/start)                                       | 提供完整中文后台组件与主题定制                                   | 企业后台                     | 与 Ant Design 属于类似定位，宜整体选择其中一套             |

Tailwind CSS 是样式工具，CSS Modules 是样式组织方式；它们与成品组件库的职责不同，可以配合使用。图表应按实际展示需求另选 Recharts 或 Apache ECharts，不用图表库替代表单、表格和权限交互。

本项目建议：管理端以 **Ant Design + 本端主题 + CSS Modules** 为主；官网按需复用 **shadcn/ui / Base UI + Tailwind** 基础。Expo 移动端使用 React Native 组件体系；需要额外库时可评估 [React Native Paper](https://callstack.github.io/react-native-paper/) 或 [Tamagui](https://tamagui.dev/)，Web DOM 组件不直接搬入原生页面。本轮未更换移动端设计系统。

## 验证方法与范围

本地生产构建通过后，在隔离的 Playwright 浏览器中，将管理端 HTML/静态资源请求转到本地生产包；API 请求仍访问真实线上 HTTPS 后端。这样可以观察实际账号和数据下的新界面，不替换线上前端，也不使用虚构业务数据。

检查登录、工作台、账号列表、新建账号弹窗（仅打开并取消）、角色、字典、字段、雪场表单、当前导航、移动抽屉及退出；覆盖 1440px、768px、390px，并检查页面横向溢出。另运行既有认证/权限/账号/角色/工作台等相关测试、边界检查、lint 和类型检查。结果见 [本轮验证记录](../validation/admin-ui-20261105.json)。这不代表全部业务提交、所有角色授权组合或物理移动设备均已验收。

最终结果：管理端 134 个测试文件、2687 项测试通过；生产构建含 TypeScript 检查和 standalone 打包通过，lint、格式和依赖边界通过。13 个代表界面状态检查通过，20 个导航入口分别在 1440px 和 390px 下共 40 项布局检查通过，浏览器无未处理页面异常。手机全局雪场筛选栏曾出现 21px 溢出，已通过换行与表格内部滚动修复。测试命令曾误以管理端别名配置包含官网测试，已停止并明确限定管理端目录重新通过，原始失败日志保留。

浏览器记录、截图和构建日志位于本机 `D:/linji-local/20261105/admin-ui/`；私有凭证沿用外部私有文件，未写入本文或仓库。服务器仍运行此前部署版本，新版界面需要另行发布。
