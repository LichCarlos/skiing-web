# 扩展清单

模板只实现多应用入口、公共基础组件、主题、浏览器基础样式、环境地址读取、源码别名和基础路由。下面列出尚未实现的能力，目录占位不代表对应功能已经可用。

| 能力                     | 当前状态                                         | 接入位置或决定依据                                          |
| ------------------------ | ------------------------------------------------ | ----------------------------------------------------------- |
| 请求、认证、权限、错误   | 各端只有地址装配与空目录                         | 在 `apps/<端>/src/platform/` 按实际 API、会话和权限协议实现 |
| 本端状态与数据缓存       | 已安装 Zustand，`stores/` 为空                   | 在本端建立需要的 Store；服务器数据缓存按实际请求场景选择    |
| 数据契约                 | 没有预设接口类型或响应包裹结构                   | 根据真实后端契约定义或生成类型，并确定运行时校验方式        |
| 状态页面与复杂路由       | 未统一业务 loading/error/空态；只有静态示例路径  | 根据真实页面增加状态处理、动态参数、导航及重定向            |
| 浏览器和可访问性验证     | 已检查基础样式与焦点，未覆盖全部浏览器和辅助技术 | 按目标浏览器与页面交互补充测试                              |
| 设计 token 与组件        | 仅有基础颜色、字体、圆角及少量共享组件           | 按实际页面补充间距、状态色、组件和必要的主题模式            |
| 国际化与时区             | 格式化工具默认中文与上海时区                     | 按应用语言和时区需求配置路由、文案与业务时间规则            |
| 业务测试、CI、部署与监控 | 未提供具体实现                                   | 根据应用运行环境补充测试、构建产物、环境注入和观测方案      |

基础模板的静态检查只验证其覆盖的工程规则。应用增加业务代码后，应针对实际行为补充测试和运行验证。
